# v4.3.1 · 2026-10-26 · 机读存档自动维护；写入重试；重建断点续做

## 现象（用户实机，Mac mini + Edge，约 7600 个 Markdown）
「从现有存档重建」中途失败：`An attempt was made to write to a file or directory which could not be modified due to the state of the underlying filesystem.`。`_data/` 里残留 0 字节的 `manifest.json.crswap`、`000001.jsonl.crswap`；清单停在 `coverage: partial`、`rebuilding` 未结束（约 2857 帖）。采集过程中的单帖发布照常成功。

## 原因
File System Access 在 macOS 上偶发 InvalidStateError（同一文件上一笔写入的临时文件还没释放时）。旧代码遇到一次就整批失败，重建也只能从头再来、而且会换代。

## 修复
- `_data/` 和 Markdown 的写入遇到 InvalidStateError / NoModificationAllowedError 时，退避重试最多 6 次（0.3 秒起翻倍）；失败时 `abort()` 释放临时文件。
- 重建断点续做：清单记 `rebuilding.next`，中断后再次发起从断点继续，**不换代**；后台每批失败重试 3 次（间隔 5、10 秒）。
- 自动维护：每分钟的 tick 里最多每 10 分钟检查一次；在选了文件夹且授权正常、没在采集或巡查时，发现 `_data/` 不存在、`coverage` 不是 `full` 或上次重建中断，就自动在后台重建。用户不需要手动点。
