# My0511 存档格式规范（两个版本共用）

适用于：纯插件版（Documents/My0511-Claude，红色图标）和带 Agent 版（Documents/My0511）。两个版本写同一个存档文件夹，必须完全遵守本规范。
**参考实现**：`extension/archive-merge.js`（解析与合并）、`extension/archive-folder.js`（文件夹读写）、`extension/md.js`（生成 Markdown 与文件名）。两个版本应使用这三个文件的**同一份代码**；任何一方要改，两边同步改，并更新本文件。

## 1. 文件名
`YYYY-MM-DD tNNNNNNN 标题.md`
- 日期：1 楼发帖日期（论坛时间，即北京时间）。
- tNNNNNNN：帖子 tid。**找文件只认 tid**，不认标题。
- 标题：最新标题，`\ / : * ? " < > |` 和控制字符换成空格，连续空白压成一个，最长 60 个字符（按 JavaScript 字符串长度）。
- 旧格式 `YYYY-MM-DD 标题.md`（3.7 版）只读不写：写同一 tid 时读文件头的 `tid:` 认出来，合并后移入 `_重复备份/`。

## 2. 文件内容
```
---
标题: "帖子标题"            ← JSON 字符串
网址: https://bbs.my0511.com/f152b-t9084953z
tid: 9084953
版块: 百姓话题
分类: 百姓心声
查看: 1596

首帖: 2026-9-25 22:12
最后一楼: 2026-9-27 17:33
已存楼数: 31
改过的楼层: 7, 66           ← 没有就不写
采集时间: 2026-09-28 06:25   ← 北京时间
---
```

## 2.1 取证指纹（4.1）
- 每层楼（包括 `<details>` 里的旧版本）可带一行 `<!-- 指纹 sha256:… · 首次采集 … -->`，是这层楼正文规范文本的 SHA-256。
- 规范文本：去掉引用头那一行（`> ↩ 回复/引用 …`；浏览器原始记录里是 `@@Q|作者|时间|摘要@@` 标记）、「本帖最后由…编辑」、不可见标记、图片存档行、指纹行、行首的 `\` 转义、所有空白；正文为「（无文字）」时视为空。
- 参考实现：`archive-merge.js` 的 `canonRaw`、`canonMd`、`fingerprintRaw`、`fingerprintMd`。从浏览器记录算和从存档文件算，结果必须相同（有测试保证）。
- 核对：重新计算文件里这层楼正文的指纹，与记录的指纹一致，说明存档之后没被改过。

## 2.2 图片存档（4.1，默认关）
- 图片存在存档文件夹的 `_图片/<tid>/<楼号>-<序号>.<扩展名>`，楼层里用「图片存档」行记相对路径。
- 只存论坛自己服务器（`*.my0511.com`）上的图，单张不超过 10 MB。

## 3. 合并规则（写入前必须执行）
1. 找出文件夹里同一 tid 的全部文件（t 格式 + 旧格式）。
2. 按各自 `采集时间` 从旧到新排序，本次内容视为最新。
3. 楼层取并集，只增不减。
4. 同一楼：最新版本作正文；其他版本与已有 `<details>` 历史合在一起，去掉空白、行首 `>`、「本帖最后由…编辑」、不可见标记、指纹行、图片存档行后比较去重，按时间排成第 1、2…版。只多了指纹或图片行不算修改。
5. 重算 已存楼数、改过的楼层、首帖、最后一楼、「N 楼 · M 人」、参与者表；其他字段取最新。
6. 自检：楼层数、`<details>` 数都不得少于任何一个输入文件，否则放弃写入并报错。
7. 写前复查：读取后如文件被改（修改时间变化），重新合并，最多 3 次。
8. 写入规范文件名；同 tid 的其他文件移到 `_重复备份/`（重名加 `.dupN`）。**任何情况下不删除存档内容。**

## 4. 不可见楼层
整帖从第 1 页采到最后一页的任务完成后，本次没出现的楼层记 `hiddenAt`，渲染不可见标记；再次出现时去掉。只从中间页开始的「取新增楼层」不做这一步。

## 5. 索引 `My0511存档索引.md`
扫描文件夹里全部 t 格式文件的文件头重建（不是只列本插件采过的），按文件名倒序：
`| 首帖日期 | 标题 | 楼数 | 跟进 | 最后采集 | 原帖 |`，第三行写 `共 N 个帖子，索引更新于 …（北京时间）。` 多次导出合并成 30 秒内重建一次。

## 6. 写入方式
- 选了存档文件夹：用 File System Access 在文件夹里合并写入；后台写入放在 offscreen 页面。
- 文件夹授权失效：**不写、不退回「下载」**（下载只能整份覆盖，会冲掉合并结果），标记待写，重新授权后补写。
- 没选文件夹：只能整份写到「下载 / My0511存档」，不合并。两个版本同时使用时，**都必须选文件夹**。
- 只有两个插件可以写共用存档文件夹。带 Agent 版的本地服务只能读这个文件夹，自己的数据写到别的目录。

## 7. 机读存档 `_data/`（存档数据协议 v1，插件 4.3.0 起）
给本地阅读程序用。**只有本插件写 `_data/`，任何阅读器只读，不得在存档文件夹里写任何东西。** Markdown（第 1～6 节）不变，仍是主存档；`_data/` 的内容全部由刚写好的 Markdown 解析生成。

### 7.1 文件
```
_data/
  source.json            来源标识：{format:"my0511-archive-data", formatVersion:1, sourceId:<uuid>, createdAt}
  manifest.json          版本化清单（唯一的「就绪」信号，见 7.3）
  threads/<tid>.json     逐帖数据（见 7.2）
  journal/000001.jsonl   变更日志，每行一条 JSON；超过 2 MB 换下一个文件，最多保留 30 个文件
```
- `sourceId` 跟着文件夹走，换浏览器、换电脑继续用同一个文件夹时不变；新文件夹会生成新的 `sourceId`。
- 所有文件用「写临时文件、关闭时整体替换」的方式写，读者不会读到写了一半的 JSON（日志追加同样整体替换）。
- 目录里可能短暂出现 Chrome 的临时文件 `*.crswap`，阅读器忽略即可。
- 自动维护（4.3.1 起）：没收录全或重建中断时自动在后台重建——每个帖子写完时立即检查（4.3.2），另有每 10 分钟一次的空闲检查；也可以在设置页手动重建。

### 7.2 逐帖 `threads/<tid>.json`
| 字段 | 说明 |
|---|---|
| `format` `formatVersion` `sourceId` | 协议标识 |
| `tid` `fid` `title` `url` `board` `category` | 帖子信息；`fid` 从网址取，取不到为 `null` |
| `author` / `authorKnown` | 主题作者＝存档里 1 楼的作者；没存到 1 楼时 `author:null, authorKnown:false` |
| `createdAt` / `createdAtPrecision` / `timezone` | 首帖时间原样（论坛时间，北京时间），精度 `minute` 或 `unknown`；`Asia/Shanghai` |
| `lastFloorAt` `views` `replies` | 论坛字段，没有为 `null` |
| `floorCount` `editedFloors` `hiddenFloors` | 楼层数（含折叠短回复）、改过的楼层号、不可见楼层号 |
| `revision` | 本帖版本号，每次内容发布 +1，单调递增；内容没变的重建不加 |
| `mdFile` `mdSha256` | 对应 Markdown 的相对路径和 SHA-256（UTF-8 原文） |
| `capturedAt` | 采集时间（Markdown 头里的，北京时间到分钟） |
| `writtenAt` | 本 JSON 写完的时间（ISO 8601，UTC） |
| `capture` | 这次采集情况：`{known, mode, ok, complete, scope:'full'|'incremental', pagesRead:[起,止], totalPages, startedAt, finishedAt, reason}`；不知道时 `{known:false}`（手动导出、补写、重建） |
| `floors[]` | `{floor, floorId, author, time, timePrecision, region, device, text, quote, hidden, hiddenSince, fingerprint, firstCapturedAt, images[], edited, history[{when,text}], latestNote}` |
| `foldedFloors[]` | 折叠成「短回复」的楼层：`{floor, author, time, text, folded:true}` |

- `floorId`（论坛 pid）目前不存档，一律 `null`（未知），阅读器用 `tid:floor` 作楼层键。
- `text` 去掉了引用头（单独放在 `quote`）、指纹行、图片行、不可见标记，并把行首 `\#` 还原成 `#`。
- `fingerprint` 即 2.1 节的取证指纹，没有为 `null`。没有的数据一律给 `null`，不猜。

### 7.3 清单 `manifest.json`
```
{ format, formatVersion, sourceId, generation, seq, coverage:'partial'|'full', updatedAt, rebuiltAt,
  journal:{ files:[{name, firstSeq, lastSeq}], firstSeq },
  threads:{ "<tid>": { revision, seq, mdFile, mdSha256, jsonFile, jsonSha256, capturedAt, writtenAt, floorCount,
                       complete:true|false|null, capture, lastFailure:{at, reason, capture}|null, mdMissing? } } }
```
- `seq`：全局发布序号，每次发布或记失败 +1，**永不倒退**。
- `generation`：代。重建、或发现文件夹被旧备份覆盖（清单序号低于浏览器记录的已发布最大序号）时 +1；阅读器见到换代就全量对账。
- `coverage`：`full` 表示文件夹里所有 t 格式 Markdown 都已收录；`partial` 表示只收录了启用后写过的帖子（在设置页「从现有存档重建」后变 `full`）。
- `complete`：`true` 从第 1 页采到最后一页成功；`false` 只采了部分页（增量）；`null` 不知道（手动导出、重建）。
- `lastFailure`：最近一次采集失败或跳过的原因，不改 `revision`。只失败过、从没存档的帖子 `revision:0, mdFile:null`。
- `mdMissing:true`：清单里有、但重建时文件夹里找不到对应 t 格式 Markdown（被改名或移走）；记录保留。

### 7.4 发布顺序（就绪规则）
写 Markdown → 写 `threads/<tid>.json` → 追加日志 → **最后写清单**。清单里出现、且 `jsonSha256` 与文件实际内容一致，才算就绪。Markdown 写成但机读部分失败时，清单不前进，插件设置页显示最近的机读写入错误。

### 7.5 日志 `journal/*.jsonl`
每行：`{seq, gen, at, type, ...}`，`type`：
- `thread`：`{tid, revision, mdFile, mdSha256, jsonSha256, complete, source?}`
- `failed`：`{tid, fid, reason}`
- `rebuild_start` / `rebuild_done`、`rollback`：换代信号，读到就全量对账。
日志行先于清单写入：**只处理 `seq ≤ manifest.seq` 的行**。旧日志文件会被删除，`manifest.journal.firstSeq` 是还能读到的最小序号。

### 7.6 阅读器算法（推荐）
阅读器自己保存 `{sourceId, generation, cursor, 每帖已处理的 jsonSha256}`，存在自己的数据库里。
1. 读 `manifest.json`。读不到或解析失败：稍后重试，不要当成「没有数据」。
2. 以下任一情况做**全量对账**：`sourceId` 变了；`generation` 变了；`manifest.seq < cursor`；`cursor + 1 < journal.firstSeq`（日志缺口）。全量对账就是遍历 `manifest.threads`，只处理 `jsonSha256` 与已处理记录不同的帖子。
3. 否则**增量**：读日志里 `cursor < seq ≤ manifest.seq` 的行，按 `tid` 去清单里取最新条目。
4. 处理一帖：读 `jsonFile`，计算 SHA-256，必须等于清单里的 `jsonSha256`；不等说明正在更新，下次再读。要核对 Markdown 时同样比 `mdSha256`。
5. 以 `(tid, jsonSha256)` 去重：重启、重复通知、换代重建都不会把旧内容当新内容。`revision` 只用于排序和展示。
6. 处理完把 `cursor` 设为这次看到的 `manifest.seq`。
7. `complete !== true` 或有 `lastFailure` 的帖子，说明这次采集不完整，按「数据不完整」处理。
8. 文件夹授权失效、写入失败时插件不会发布新版本，清单停在原地；文件修改时间的变化不代表采集成功，一律以清单为准。
