# My0511 存档格式规范（两个版本共用）

适用于：纯插件版（Documents/My0511-Claude，红色图标）和带 Agent 版（Documents/My0511）。两个版本写同一个存档文件夹，必须完全遵守本规范。
**参考实现**：`extension/archive-merge.js`（解析与合并）、`extension/archive-folder.js`（文件夹读写）、`extension/md.js`（生成 Markdown 与文件名）。两个版本应使用这三个文件的**同一份代码**；任何一方要改，两边同步改，并更新本文件。

## 1. 文件名
`YYYY-MM-DD tNNNNNNN 标题.md`
- 日期：1 楼发帖日期（论坛时间，即北京时间）。
- tNNNNNNN：帖子 tid。**找文件只认 tid**，不认标题。
- 标题：最新标题，`\ / : * ? " < > |` 和控制字符换成空格，连续空白压成一个，最长 60 个字符（按 JavaScript 字符串长度）。
- 旧格式 `YYYY-MM-DD 标题.md`（3.7 版）只读不写：写同一 tid 时读文件头的 `tid:` 认出来，合并后移入 `_重复备份/`。

## 2.1 取证指纹（4.1）
- 每层楼（包括 `<details>` 里的旧版本）可带一行 `<!-- 指纹 sha256:… · 首次采集 … -->`，是这层楼正文规范文本的 SHA-256。
- 规范文本：去掉引用头那一行（`> ↩ 回复/引用 …`；浏览器原始记录里是 `@@Q|作者|时间|摘要@@` 标记）、「本帖最后由…编辑」、不可见标记、图片存档行、指纹行、行首的 `\` 转义、所有空白；正文为「（无文字）」时视为空。
- 参考实现：`archive-merge.js` 的 `canonRaw`、`canonMd`、`fingerprintRaw`、`fingerprintMd`。从浏览器记录算和从存档文件算，结果必须相同（有测试保证）。
- 核对：重新计算文件里这层楼正文的指纹，与记录的指纹一致，说明存档之后没被改过。

## 2.2 图片存档（4.1，默认关）
- 图片存在存档文件夹的 `_图片/<tid>/<楼号>-<序号>.<扩展名>`，楼层里用「图片存档」行记相对路径。
- 只存论坛自己服务器（`*.my0511.com`）上的图，单张不超过 10 MB。

## 3. 合并规则（写入前必须执行）
1. 找出文件夹里同一 tid 的全部文件（t 格式 + 旧格式）。
2. 按各自 `采集时间` 从旧到新排序，本次内容视为最新。
3. 楼层取并集，只增不减。
4. 同一楼：最新版本作正文；其他版本与已有 `<details>` 历史合在一起，去掉空白、行首 `>`、「本帖最后由…编辑」、不可见标记、指纹行、图片存档行后比较去重，按时间排成第 1、2…版。只多了指纹或图片行不算修改。
5. 重算 已存楼数、改过的楼层、首帖、最后一楼、「N 楼 · M 人」、参与者表；其他字段取最新。
6. 自检：楼层数、`<details>` 数都不得少于任何一个输入文件，否则放弃写入并报错。
7. 写前复查：读取后如文件被改（修改时间变化），重新合并，最多 3 次。
8. 写入规范文件名；同 tid 的其他文件移到 `_重复备份/`（重名加 `.dupN`）。**任何情况下不删除存档内容。**

## 4. 不可见楼层
整帖从第 1 页采到最后一页的任务完成后，本次没出现的楼层记 `hiddenAt`，渲染不可见标记；再次出现时去掉。只从中间页开始的「取新增楼层」不做这一步。

## 5. 索引 `My0511存档索引.md`
扫描文件夹里全部 t 格式文件的文件头重建（不是只列本插件采过的），按文件名倒序：
`| 首帖日期 | 标题 | 楼数 | 跟进 | 最后采集 | 原帖 |`，第三行写 `共 N 个帖子，索引更新于 …（北京时间）。` 多次导出合并成 30 秒内重建一次。

## 6. 写入方式
- 选了存档文件夹：用 File System Access 在文件夹里合并写入；后台写入放在 offscreen 页面。
- 文件夹授权失效：**不写、不退回「下载」**（下载只能整份覆盖，会冲掉合并结果），标记待写，重新授权后补写。
- 没选文件夹：只能整份写到「下载 / My0511存档」，不合并。两个版本同时使用时，**都必须选文件夹**。
- 只有两个插件可以写共用存档文件夹。带 Agent 版的本地服务只能读这个文件夹，自己的数据写到别的目录。
