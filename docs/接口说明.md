# My0511 插件接口说明 v1.2（插件 4.2.0 起；v1.1 为 4.1.0，v1.0 为 4.0.0）

## 分工
| | 负责方 | 位置 |
|---|---|---|
| 插件核心（采集、存档、定时发帖、人工验证、工作台基础功能）和本接口 | Claude | `<collector-repository>`（上游，打 git 标签发布，如 `v4.0.0`） |
| 本地服务（Agent）、扩展模块（addons）、最终产品的合并与封装 | ChatGPT | `<agent-repository>` |

最终产品 = 插件核心（原样）+ ChatGPT 的扩展模块 + 本地服务，由 ChatGPT 打包。

## 1. 文件接口：存档文件夹
- 格式、文件名、合并规则见 [存档格式规范](存档格式规范.md)。
- **只有插件写存档文件夹**。本地服务和扩展模块只读；本地服务自己的数据写到别的目录（可以自由新建、写入）。

## 2. 扩展模块接入点
| 接入点 | 文件 | 说明 |
|---|---|---|
| 后台（service worker） | `extension/addons/addons.js` | `sw.js` 在核心加载完后 `importScripts` 它；可在里面再 `importScripts('addons/xxx.js')`。出错只打日志，不影响插件。 |
| 工作台页面 | `extension/addons/control-addon.js` | `control.html` 最后加载；界面放进 `<div id="addons"></div>`。 |
| manifest 增补 | 打包时处理 | 例如本地服务需要的 `http://127.0.0.1:17851/*` 权限、产品名称、版本后缀，由打包脚本合并进 manifest，**不改上游 manifest 文件**。 |

纯插件版里这两个 addons 文件是空的占位文件；打包时用 ChatGPT 的版本替换。
扩展模块自己的页面、脚本放在 `extension/addons/` 下，不和核心文件同名。

## 3. 后台接口 `self.My0511API`（v1.2，已冻结对象；v1.1、v1.2 只新增，不改已有行为；唯一例外见 postOnce 的 guard 参数）
所有方法返回 Promise。

### 状态与控制
- `status()` → `{haltCollect, haltPost, challenge, job, queued, posts, log, build, profileId}`
- `pause(scope)` / `resume(scope)`：`scope` 为 `'all' | 'collect' | 'post'`。人工验证未完成时 `resume` 会报错。

### 采集与浏览器记录
- `getThread(tid)` → 浏览器里存的完整记录（`thread`、`floors`，楼层含 `text`、`history`、`hiddenAt`、`fp`（取证指纹）、`imageUrls`、`images` 等），没有则 `null`。
- `listThreads()` → 帖子摘要列表 `{tid, fid, title, url, fileName, floors, updatedAt, exportedAt, watch}`。
- `enqueue([{tid, fid, title}])` → 加进采集队列（已存的从存到的那页接着采，会参考存档文件夹里的文件）。

### 存档
- `writeArchive(tid)` → 立即把这个帖子合并写入存档文件夹（按规范合并）。
- `knownFloors([tid])` → `{tid: 文件里最大楼号}`；没选文件夹或没授权时返回 `{}`。
- `archiveStatus()`（v1.2）→ `{mode: 'folder'|'downloads', directoryName, permission: 'granted'|'prompt'|'denied'|null, pendingWrites, folderAuthNeeded, lastWriteError: {tid, error, at}|null}`。不含绝对路径和文件句柄。`pendingWrites` 是浏览器里已采到、还没写进存档文件的帖子数；`lastWriteError` 在之后任何一次写入成功时清除。

### 人工验证
- `challenge()` → 当前待处理的验证（没有则 `null`）。
- `refreshChallenge()` → 重新读取验证页面，返回最新题目（含 `problem`、`revision`）。
- `answerChallenge({id, revision, answer})` → 把**真人给出的答案**填进原验证页面提交。插件不做任何自动求解；接口只接受数字答案，同一题目版本只提交一次。
- `verifyChallenge(id)` → 检查是否已回到正常论坛页面，通过后清除验证状态。

### 提醒（v1.1 新增）
- `alerts()` → 提醒列表（最新在前，最多 300 条）。每条：`{id, at, read, kind, tid, floor, author, title, url, message, keyword?}`，`kind` 为 `reply`（有人引用或 @ 你）、`edit`（关注的帖子或 ID 改楼）、`hidden`（关注的帖子或 ID 的楼不可见了）、`keyword`（关键词出现在新帖标题或新楼正文）。只针对最近 3 天内发的楼。
- `markAlertsRead(ids)` → 标为已读；不传 ids 表示全部。
- `alertsSince({cursor, limit})`（v1.2）→ `{items, nextCursor, truncated, latest}`：按 `seq` 从旧到新返回 `cursor` 之后的提醒，`limit` 默认 100、最多 500。每条提醒有全局递增的 `seq`（4.2 之前的旧提醒没有 `seq`，不会返回）。`truncated=true` 表示 `cursor` 之后有提醒已被清理（中间有缺口）；此时 `nextCursor` 仍可继续使用。
- `ackAlerts({consumer, cursor})`（v1.2）→ 记录消费方（名称只能用字母、数字、`_ . -`，例如 `agent`）处理到哪个 `seq`，只增不减。**和用户的「已读」无关**，不会改变 `read`。
- 保留期限（v1.2）：至少保留最近 300 条；只要有消费方登记过确认位置，比所有消费方确认位置都新的提醒额外保留，最多 2000 条、最长 30 天。用户在工作台点「清空」会清掉全部提醒（`seq` 继续递增）。
- `settings()` → `{myName, watchUsers, keywords, imageUsers}`（用户在工作台设置的「我的 ID」「关注的 ID」「关键词」「存图的 ID」）。只读；修改由用户在工作台进行。

### 发帖（只有这两条路）
- `fillReply({tid, fid, message})` → 打开回复页并填入正文，**永不点发表**。
- `postOnce({ref, tid, fid, message}, guard)` → 一次性直接发表一条回复。
  - `guard({ref, tid, fid, message})` 是必填的异步确认函数，发送前会多次调用；任何一次抛错就不发。参数是冻结的公开形状（v1.2 起固定为这四个字符串字段；v1.1 传的是内部队列项，下游不应依赖其他字段）。
  - 同一个 `ref` 只尝试一次；浏览器重启后未完成的任务一律不发、不补发。
  - 仍受发帖间隔、每日上限、发帖暂停、人工验证等全部现有保护。

### 事件 `on(event, fn)` → 返回取消函数
`alert (提醒对象，v1.1)` · `threadUpdated {tid, floors}` · `archiveWritten {tid, fileName, floors, revision, capturedAt}`（v1.2 起带 `revision`＝这次写入时间，同一帖子单调递增；`capturedAt`＝写入内容对应的最后采集时间。`capturedAt` ≥ 某条提醒的 `at`，说明这条提醒对应的版本已写进存档） · `jobDone {tid, skipped}` · `challenge (对象或 null)` · `postHalted` · `postResumed` · `collectHalted` · `collectResumed` · `postQueueChanged {size}`
扩展模块应在 `postHalted` 时取消自己的自动发表任务。

### 扩展模块存储
- `store.get(key, 默认值)`、`store.set(key, 值)`、`store.update(key, fn, 默认值)`：实际键为 `addon:<key>`，key 只能用字母、数字、`_ . -`。
- 扩展模块不要直接读写插件核心的存储键。

### 页面消息
扩展模块自己的页面与后台通信时，消息 `type` 统一用 `ADDON_` 前缀；插件核心不处理这类消息。

## 4. 规则
1. 扩展模块和本地服务**不修改插件核心文件**（`extension/` 下除 `addons/` 以外的一切）。需要新接口或改动核心行为时，写一份需求说明交给用户，由 Claude 在上游实现并发布新标签。
2. 验证码答案只能来自真人；不得加入自动求解。
3. 插件核心升级时，最终产品整体替换 `extension/`（保留 `addons/` 为 ChatGPT 版本）重新打包。
4. 接口有不兼容改动时 `My0511API.version` 主版本号加 1，并在本文件写明迁移方法。
